# Home Materia Research

## 目标

本 skill 的任务不是替《居家本草》“证明”一个预设的性味或功效，而是回答：

1. 我们研究的究竟是哪一种食品 / 制品？
2. 与它直接相关的人体证据是什么？
3. 证据有多可靠，适用于什么剂量、形态、人群和时间尺度？
4. 哪些结论只来自成分、动物、体外或相似食品，不能直接外推？
5. 有哪些安全性、不良反应、药物相互作用或特殊人群问题？
6. 古代本草 / 食疗文献中是否有可可靠对应的母本？
7. 现代事实在多大程度上可以支持性味、食效或拟归经的本草映射？
8. 什么时候继续检索已经不再改变当前版本的判断？

必须先读取并遵守：

- `docs/居家本草编纂凡例-v1.0.md`
- `catalog/README.md`
- 若目标条目已有研究文件，先读取现有研究底稿，避免重复工作。

本 skill 只生成或更新研究底稿，不直接生成出版正文。

## 核心纪律

### 1. 不以结论为检索词的唯一方向

若问题是“巧克力是否疏肝解郁”，不得只检索支持 mood / depression / anxiolytic 的研究。

必须同时寻找：

- 无效结果；
- 相反结果；
- 剂量与加工差异；
- 安全性；
- 研究资金与利益冲突；
- 与真实食用形态不一致的证据。

### 2. 人体效应与本草映射分开

先判断现代人体命题，再讨论本草映射。

禁止：

> 现代研究显示 X → 因此必然“入某经 / 清热 / 疏肝 / 健脾”。

人体效应使用项目的 **E-A ～ E-0**；本草映射使用 **M-I ～ M-0**。

### 3. 研究食品本身，不让单一成分替代食品

所有关键证据必须标注 **证据距离 D0–D4**，详见
`references/identity-and-transferability.md`。

原则上：

- D0 / D1 可作为直接或近直接食品证据；
- D2 需要显著降格解释；
- D3（孤立成分）主要用于机制；
- D4（相似食品 / 理论类比）只能提供假说。

### 4. 资料多不等于无限研究

先指定 R1 / R2 / R3，再按项目停止规则工作。

“还有论文没读”不是继续研究的充分理由；当新增文献预计不改变结论等级、主要矛盾或安全判断时，应停止。

### 5. 搜索结果、摘要和 AI 总结都不是原始证据

重要结论尽量核到论文全文、结构化摘要、权威报告或官方原始资料。

只有摘要可得时，必须标记：

`full_text_status: abstract_only`

不得从搜索引擎 snippet 推断关键数值、研究方法或结论强度。

### 6. 引用必须可核验

关键论文至少核验：

- 题名；
- 作者；
- 年份；
- 期刊；
- DOI / PMID / PMCID（若有）；
- 是否有更正、撤稿或重要勘误。


### 7. Identity 可以被研究修正

Catalog 给出的是研究起点，不是不可修改的结论。

如果正式检索发现：

- 名称过宽；
- 同名产品实际是多个不同食品；
- 应拆成母条 / 子条；
- 原以为没有传统母本、实际存在；
- 研究对象与目录定义不一致；

可以提出 identity revision，并记录：

- 原 entry ID；
- 新 entry ID / canonical name；
- 修改理由；
- Catalog 应采取的动作。

不得为了保持原目录而研究一个无法稳定定义的对象。

### 8. 复合食品优先查 Composition & Exposure

对奶茶、方便面、火锅等复合食品，人体长期结局可能很少，但以下资料本身非常重要：

- 常见份量；
- 糖、钠、咖啡因、酒精等关键暴露；
- 产品间变异；
- 配方 / toppings / 调味包；
- 少糖、去料、换奶等定制变量。

组成证据不强行使用 E 分级；E 继续只评价人体健康 effect claim。

### 9. 多个 Meta 不等于多套独立证据

若多个系统综述 / Meta 高度共享同一批基础研究，应在 dossier 标记 `evidence_base_overlap`。

不得用“有 4 篇 Meta 支持”来制造独立重复的错觉。

### 10. 食用温度与本草寒热分开

冰饮、热饮属于 serving condition。

禁止：

> 冰的 → 性寒  
> 热的 → 性热

如果物理温度确实影响症状、胃肠反应或场景，应作为 timing / serving variable 研究。

### 11. 传统母成分不能机械相加

复合食品中的茶、乳、糖、香辛料等可以各有传统资料，但这些资料对复合食品通常只是类比或母本背景。

不得把多个母成分的性味、归经、功效直接相加，生成一个现代复合食品的本草结论。

## 工作流

详细规则见 `references/workflow.md`。执行顺序不可随意颠倒：

1. **Load**：读取项目凡例、目录规则与已有研究。
2. **Identify**：定义食品 / 植物 / 制品身份；若检索证明原条目边界不成立，允许修改 canonical identity，并记录 `identity_revision` 与 Catalog action。
3. **Scope**：确定 R1 / R2 / R3，列 3–8 个核心问题。
4. **Plan**：为核心问题建立 PECO / PECOT 或“食品矩阵 × 因素 × 结局”框架；复合食品先列组成、份量和关键真实暴露。
5. **Search**：按来源层级分层检索并记录搜索日志。
6. **Screen**：按直接性、研究设计、对象身份和可转移性筛选。
7. **Extract**：建立证据卡，保留效应量、置信区间、剂量、食品形态、资金来源。
8. **Appraise**：评价风险偏倚、直接性、一致性、精确性、发表偏倚和可推广性。
9. **Synthesize**：按“结局 / 命题”综合，不按“论文”逐篇罗列；多个 Meta / review 一致时检查其基础研究是否高度重叠。
10. **Grade E**：为每个具体人体效应评 E-A ～ E-0。
11. **Trace TCM concepts**：涉及性味、归经、脏腑、证候、功效等术语时，先做概念溯源与时代分层。
12. **Map M**：在 E 与概念溯源之后独立评定本草映射证据等级，列出支持、反证与替代解释。
13. **Jev mapping（可选但推荐）**：Research Dossier 完成后，可调用 `../home-materia-jev-mapping/SKILL.md`，把正式说明文档交给 Jev 得到四气、五味、五脏归经原生 score。Jev score 与 M grade 并列保存；不得用 Jev score 提升 M，也不得用 M 修改 Jev score。
14. **Safety**：单独检索和总结不良反应、相互作用和特殊人群。
15. **Stop**：依据 R 等级和证据饱和判断停止。
16. **Reference audit**：把关键引文、DOI/PMID、古籍版本与数据库入口列入底稿，供作者与读者复核；不设置强制人工复审门槛。
17. **Write dossier**：输出研究底稿，不输出出版正文。

## 默认检索层次

### Layer A｜权威概览与证据综合

优先寻找：

- 系统综述 / Meta-analysis；
- Cochrane；
- 政府或权威机构的证据综合；
- 食品 / 营养领域的 USDA NESR、EFSA、FDA、WHO、Codex 等；
- 草药 / 天然产物领域的 WHO、EMA/HMPC、药典、FDA botanical guidance 等。

作用：建立证据地图、找到关键词、判断已有综述截止日期。

### Layer B｜直接人体证据

围绕实际食品 / 制品寻找：

- RCT / 交叉试验；
- 前瞻性队列；
- 其他直接人体研究；
- 剂量、时机、加工差异；
- 必要时临床试验注册资料。

### Layer C｜安全性

独立检索：

- 不良事件；
- 病例 / 病例系列；
- 药物相互作用；
- 过敏；
- 特殊人群；
- 权威风险评估与监管警示。

安全信号不因研究设计层级较低而自动忽略。

### Layer D｜机制与成分

仅在下列情况下展开：

- 解释已观察到的人体结果；
- 为本草映射提供辅助合理性；
- 解释加工为何改变作用；
- 澄清安全机制。

不得为了“补足证据”无限追踪细胞通路、分子对接或单一成分药理。

### Layer E｜传统文献与中医概念

若存在传统母本或涉及中医核心概念，读取 `references/tcm-concepts-and-databases.md`，并：

- 尽量查原文；
- 记录书名、时代、版本、卷次 / 页码、原文与上下文；
- 核对古今名称、物种、部位和炮制是否能对应；
- 后世注解不得倒灌给更早文献；
- 区分原典用语、后世理论化、现代教材标准化三层；
- 结构化中医数据库只作发现与交叉核对工具，不能代替原典或现代人体证据。

## 研究设计与评价

不使用“期刊影响因子 = 证据强度”。

按研究设计选择合适的方法学框架：

- RCT：参考 RoB 2；
- 非随机干预：参考 ROBINS-I；
- 暴露 / 饮食观察研究：参考 ROBINS-E，并特别检查膳食暴露测量、残余混杂、反向因果、总能量与替代关系；
- 系统综述：检查检索完整性、纳入标准、偏倚评价、异质性和发表偏倚，可参考 AMSTAR 2；
- 报告质量：CONSORT / STROBE / PRISMA 只帮助判断报告是否完整，不代替风险偏倚评价。

对于草药 / 天然产物研究，还必须评价干预物是否描述充分，详见
`references/identity-and-transferability.md`。

## 研究预算

### R1｜简明

- 1–3 个核心问题；
- 优先权威综述 + 直接人体证据 + 安全；
- 无直接证据时尽快停止；
- 机制只保留解释当前结论所必需的部分。

### R2｜标准（默认）

- 3–8 个核心问题；
- 每个问题先寻找 1–3 个高质量、较新的证据综合；
- 补其检索截止日期后的关键人体研究；
- 必须主动找相反证据和安全信号；
- 到达证据饱和即停止。

### R3｜重点

用于咖啡、茶、巧克力、酒类等高文献密度或方法学示范条目。

允许：

- 比较多个综述；
- 深入处理剂量、时机、加工、人群亚组；
- 对重大争议回到关键原始研究；
- 建更完整的 evidence map。

仍不以“读完所有论文”为目标。

## 输出位置与格式

默认在：

正式条目默认在：

`references/entries/<entry-id>/research.md`

若对象是 `entry_type: research_parent` 且 `publish: false`，则使用：

`references/shared/<entry-id>/research.md`

Research Parent 只保存多个子条共用的背景证据；任何子条引用时必须重新判断 D。

建立或更新研究底稿。

使用模板：

`templates/research-dossier.md`

至少包括：

- 条目身份与边界；
- 研究深度与证据截止日期；
- 核心问题；
- 搜索日志；
- 传统来源；
- 组成与真实暴露（复合食品 / 产品差异大时）；
- 现代证据地图；
- 逐命题 E 等级；
- 安全性；
- 机制；
- 本草映射候选与 M 等级；
- 主要反证 / 冲突；
- 未知；
- 证据饱和 / 停止理由；
- Claim Ledger（正文允许写到什么强度、`claim_mode`、以及对应引用）。

## 完成前检查

任何一项“不”都不能宣称研究底稿完成：

- [ ] 研究对象的食品 / 植物 / 制品身份是否足够明确？若检索改变了对象，是否记录 identity revision？
- [ ] 核心问题是否在预算范围内？
- [ ] 复合食品是否先查过真实组成、份量与关键暴露？
- [ ] 是否优先查过高层级证据综合？
- [ ] 是否补查了综述截止日期后的关键研究？多个综述是否存在明显 evidence-base overlap？
- [ ] 是否主动寻找相反证据？
- [ ] 是否单独查过安全性？
- [ ] 每项关键证据是否标 D0–D4？
- [ ] 是否把孤立成分与真实食品区分开？
- [ ] E 是否按具体 outcome / claim 评定，而不是给食品总分？
- [ ] Claim 是否标明 effect / association / composition / safety / traditional / mapping，避免写作时改变事实类型？
- [ ] M 是否在 E 之后独立推演？
- [ ] 关键数字、DOI / PMID、古籍版本和数据库入口是否完整列出，便于复核？
- [ ] 是否记录 evidence cutoff？
- [ ] 是否说明为什么现在可以停止？

若直接人体证据不存在，允许并应当得出：

> **目前无足够直接人体证据；停止扩张间接机制检索。**
