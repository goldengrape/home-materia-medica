# 《居家本草》内容与数据模型

> 版本：v1.0-draft
> 作用：定义核心对象、路径、状态与接口，避免后续文件各自发明格式。

## 一、核心对象

### CM-OBJ-001｜Entry
一本书中的唯一研究对象。最小字段：

```yaml
id:
name:
aliases: []
entry_type: food | processed_food | composite_food | beverage | fermented_food | supplement | scene | research_parent
publish: true
volume:
section:
tags: []
parent_entries: []
related_entries: []
research_depth: R1 | R2 | R3
status:
```

### CM-OBJ-002｜Research Dossier
- 一个正式 Entry 对应一个主研究底稿。
- 正式条目路径：`references/entries/<entry-id>/research.md`。
- 共享 Research Parent 路径：`references/shared/<entry-id>/research.md`。
- 保存“搜”阶段的来源、证据卡，以及“整”阶段的详细证据综合、E/D、安全、Concept Trace、冲突、未知和停止理由。
- 不保存最终 Jev 分类，不负责正文表达。

### CM-OBJ-002A｜Research Parent

Research Parent 是不直接发布给读者的共享研究节点，用于多个正式条目复用同一批背景证据。

```yaml
id:
entry_type: research_parent
publish: false
child_entries: []
inheritance_rule: regrade_D_on_use
```

只有存在明显共享证据、确实能减少重复研究时才建立。子条引用母页时必须重新判断 D，不能无条件继承结论。

### CM-OBJ-002B｜Summary Document

Jev 的正式生产输入。

路径：

`references/entries/<entry-id>/summary.md`

它从 `research.md` 派生，使用连续自然语言整理：

- 食品身份与加工；
- 传统背景；
- 现代人体效应；
- 安全与限制；
- 支持、反证、冲突和替代解释；
- 必要的机制解释。

不得为了 Jev 预写最终四气、五味、归经、阴阳增减、Jev score 或 M grade。

### CM-OBJ-002C｜Materia Mapping Record

分类层的权威记录。

路径：

`references/entries/<entry-id>/mapping.md`

保存：

- Summary Document ref / hash；
- Jev v0.4 版本和 actual model；
- 四气 probabilities；
- 五味 scores；
- 五脏归经 scores；
- 每经主方向 Choice 与完整 probabilities；
- 针对分类命题逐项评定的 M-I ～ M-0；
- 支持、反证、替代解释；
- 最大允许写作强度。

Jev 原始结果与 M grade 独立，不互相修正。

### CM-OBJ-003｜Evidence Record
现代研究至少记录 citation、DOI/PMID、设计、人群、样本、食品形态、剂量、对照、时长、结局、效应量、风险偏倚、D、资金与冲突、全文状态以及 supports / does_not_support。

### CM-OBJ-004｜Claim
正文可能使用的一个可核查命题。Claim Ledger 是“判 → 写”的接口，不是独立生产阶段。

至少记录：`claim_id`、`entry_id`、文本、`claim_mode`、E、M、D 范围、适用范围、来源、Jev mapping ref（若适用）、allowed wording、status。

```yaml
claim_mode: effect | association | composition | safety | traditional | mapping
```

其中：
- `effect`：人体干预 / 因果效应命题；
- `association`：观察性关联，不得在写作层自动变成因果；
- `composition`：食品组成与真实暴露，不强行使用 E；
- `safety`：风险、过敏、相互作用与特殊人群；
- `traditional`：传统文献直接记载；
- `mapping`：现代本草拟释，使用 M。

### CM-OBJ-005｜TCM Concept
- 高频中医概念的工作定义和历史溯源。
- 建议路径：`concepts/<concept-id>.md`。

### CM-OBJ-006｜Traditional Source
记录具体传统来源：书名、作者/时代、版本、卷次/页码、原文、上下文、身份对应问题。

### CM-OBJ-007｜Database Relation

```yaml
database:
checked_date:
entity_a:
relation:
entity_b:
relation_type: curated | literature_mined | integrated | predicted | mapped
source_reference:
direct_evidence_retrieved: yes | no
notes:
```

### CM-OBJ-008｜Scene
生活场景/食方的身份由“食品组合 + 时间 + 剂量 + 行为方式”构成，不简单复制单品条目。

## 二、条目状态

状态与四阶段主流程对应：

```text
planned
→ collecting
→ summarizing
→ classified
→ drafting
→ draft_ready
→ qa
→ publish_ready
→ published
```

旧状态 `researching` 可视为 collecting / summarizing 的历史总称；`research_ready` 对应 summary 已冻结、可以进入分类。

允许：`blocked`、`deferred`、`update_needed`。

`research_ready` 只表示当前版本达到停止规则、来源链完整；不表示研究领域已经终结，也不表示必须经过独立人工复审。

## 三、ID 约定

项目级：
- PB-GOAL / PB-AC / PB-CON
- ARC-WS / ARC-IF / ARC-STOP
- CM-OBJ / CM-STATE
- QA-CHECK
- RM-PHASE / RM-TASK
- DEC / PROB

条目级建议：

```text
<entry-id>-Q-001      核心研究问题
<entry-id>-SRC-001    来源
<entry-id>-CLM-001    Claim
<entry-id>-MAP-001    本草映射
```

稳定 ID 一旦被 TRACE 或正文引用，避免随意重命名。

## 四、推荐目录结构

```text
docs/        项目规则、规划与路线
catalog/     收录边界与条目身份
concepts/    中医概念工作定义
skills/      可复用工作流
references/entries/  正式条目的 research.md / summary.md / mapping.md
references/shared/   不直接发布的共享 Research Parent
entries/     单品正文
scenes/      生活场景正文
qa/          一致性报告
okf/         派生 AI 检索层
project/     机器可读状态与 trace
site/        GitHub Pages 构建配置（后续）
dist/        本地构建产物，不作为正文事实来源（后续）
```

不是所有目录都立刻创建；按路线图逐步建立。

## 五、内容流

权威主流程见 `docs/生产流程.md`：

```text
Catalog entry
   ↓
搜 → research.md
   ↓
整 → summary.md
   ↓
判 → mapping.md
   ↓
写 → entries/<entry-id>.md
   ↓
QA
   ↓
publication
```

Research Dossier 是证据事实来源；Summary Document 是 Jev 的正式输入；Mapping Record 是分类与 M 的权威来源；Claim Ledger 是“判 → 写”的接口；Entry 正文是读者界面；QA 只报告问题，不成为新的事实来源。

## 六、版本原则

- 方法学改变：更新 docs 版本，并标记受影响条目；
- 新研究：更新该 dossier 的 evidence cutoff；
- Claim 强度改变：先改 Claim Ledger，再改正文；
- 目录身份改变：先改 catalog，再迁移 dossier / entry；
- OKF 永远从上游资料派生，不反向成为权威来源。

## 七、发布数据流

```text
entries/*.md + scenes/*.md + front matter
        ↓
   publication build
     ↙          ↘
GitHub Pages   GitHub Release
                 ├─ Markdown bundle
                 └─ EPUB
```

发布构建只能转换格式、生成导航和索引，不得改写正文事实或证据强度。

项目不定义图片对象；正文模型中不需要 `image`、`figure`、`caption` 或图片版权字段。如未来确有必须表达的结构信息，优先使用 Markdown 表格、列表、文本框或可访问的纯文本结构。
