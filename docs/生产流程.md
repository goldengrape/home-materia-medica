# 《居家本草》生产流程

> 状态：current  
> 作用：定义单个食材从资料到正文的唯一主生产链。  
> 口令：**搜 → 整 → 判 → 写**。

## 一、总流程

```text
1. 收集资料
   ↓
2. 整理总结资料
   ↓
3. Jev 分类 + M 证据标注
   ↓
4. 根据资料与分类撰写正文
```

这是项目对外和对执行器都应使用的主流程。

D、E、Concept Trace、停止规则、Jev、M、Claim Ledger 等不是与这四步平级的新阶段，而是四个阶段内部的工具。

---

## 二、第一阶段｜搜：收集资料

### 目标

回答：

> 关于这个食材，我们实际查到了什么？

这一阶段只收集和核验事实，不预设四气、五味、归经或阴阳增减答案。

### 输入

- Catalog entry；
- entry ID / canonical identity；
- R1 / R2 / R3 研究深度；
- 已有 Research Parent；
- 项目凡例与检索规则。

### 内部工作

包括但不限于：

- Identity Card；
- 核心问题；
- Search Log；
- Composition & Exposure；
- 传统来源；
- 现代人体研究；
- 安全资料；
- 加工、剂量、时机；
- 机制资料；
- 相反结果和冲突；
- Evidence Record；
- D0–D4 直接性记录；
- DOI / PMID / 古籍版本核验。

### 输出

`references/entries/<entry-id>/research.md`

Research Dossier 保存：

- 原始来源；
- 证据卡；
- 研究质量；
- 事实结果；
- 安全性；
- 冲突和未知。

**本阶段不得为了后续 Jev 分类而定向补写答案。**

---

## 三、第二阶段｜整：整理总结资料

### 目标

回答：

> 把已经查到的资料放在一起，这个食材目前可以怎样准确地描述？

这一阶段把散乱资料整理成可阅读、可推理、可追溯的说明文档。

### 内部工作

- 风险偏倚与证据体评价；
- 按 outcome 综合；
- E-A ～ E-0；
- 机制只用于解释事实；
- 必要的 Concept Trace；
- 支持与反证同时保留；
- 替代解释；
- evidence-base overlap；
- evidence cutoff；
- stopping status / reason；
- Reference audit。

### 输出 A｜Research Dossier 完成版

`research.md` 中保留详细研究过程和来源链。

### 输出 B｜Summary Document

推荐路径：

`references/entries/<entry-id>/summary.md`

Summary Document 是从 Research Dossier 派生的连续自然语言说明文档，也是 **Jev 的唯一正式生产输入**。

它应当：

- 足够完整，使分类依据来自文档内部；
- 保留支持、反证、限制和替代解释；
- 保留食品身份、加工、剂量和重要传统背景；
- 不把论文逐篇堆砌成摘要列表；
- 不为了 Jev 特制结构化 feature packet。

### Summary Document 禁止提前写入

- 最终四气；
- 最终五味；
- 最终归经；
- 最终阴-/阴+/阳-/阳+；
- Jev score；
- M grade；
- “暂不归经”等分类结论。

若传统原始来源本身明确记载某性味或归经，可作为**传统事实**如实保留并标明来源；不能伪装成现代食品的最终分类。

---

## 四、第三阶段｜判：Jev 分类 + M 证据标注

### 目标

回答两个不同问题：

1. Jev 根据 Summary Document 倾向怎样分类？
2. 这些分类目前有多强的可追溯证据支持？

### Step 3A｜Jev v0.4 分类

输入：

`summary.md`

Jev 固定输出：

### 四气

```text
寒 / 凉 / 平 / 温 / 热
```

### 五味

```text
酸 / 苦 / 甘 / 辛 / 咸
```

### 五脏归经

```text
心 / 肝 / 脾 / 肺 / 肾
```

### 每经主方向

```text
阴-
阴+
阳-
阳+
```

归经和主方向：

> **语义上级连，计算上同步。**

即理论上先解释“作用在哪里”，再解释“该经阴阳向哪个方向变化”；API 层在一次 Jev request 中同步计算。

所有原生 Choice probabilities / Noul 必须保存。

### Step 3B｜给分类标 M

Jev 分类完成后，再回到 Research Dossier，对**已经出现的分类命题**逐项标注 M-I ～ M-0。

例如：

```text
酸奶
脾：Jev 0.62
脾主方向：阳+
M：M-0
```

这里：

- Jev score = 模型分类倾向；
- M grade = 这项本草映射的证据强度。

二者独立。

禁止：

- M 低就修改、隐藏或压低 Jev score；
- Jev score 高就提升 M；
- 把 Jev probability 写成经过经验校准的真实世界概率。

### 输出

推荐路径：

`references/entries/<entry-id>/mapping.md`

至少保存：

- Summary Document ref / hash；
- Jev reasoning / five-shot / model version；
- 四气完整 probabilities；
- 五味全部 scores；
- 五脏全部 scores；
- 每经主方向 + 四项 probabilities；
- 每项分类的 M grade；
- 支持；
- 反证；
- 替代解释；
- 可供正文使用的最大表述强度。

### 传统习惯词

“疏肝、健脾、温中、润肺、化湿、生津”等属于**分类后的表达层**。

底层保持：

```text
归经 + 阴阳增减 + 语境
```

例如：

```text
肝 + 阳- → 疏肝 / 平肝等候选表达
脾 + 阳+ → 健脾 / 温中等候选表达
肺 + 阴+ → 润肺 / 生津等候选表达
```

不是严格一对一。

## 五、第四阶段｜写：根据资料与分类撰写正文

### 目标

回答：

> 怎样把已经核实的资料和已经完成的分类，准确、清楚、有趣地讲给读者？

### 正文输入

写作层应读取：

1. `research.md`：需要追溯细节时使用；
2. `summary.md`：事实和整体说明的主要输入；
3. `mapping.md`：Jev 分类、M grade、阴阳主方向；
4. Safety / conflicts / unknowns；
5. 可用来源和 Claim Ledger。

### 写作层可以做

- 组织叙事；
- 压缩和解释；
- 选择适当传统习惯词；
- 把 Jev 原子分类翻译成普通读者可理解的本草语言；
- 根据 E / M 调整文字强度；
- 安排引用、参见和提示框。

### 写作层不可以做

- 重新检索后静默加入新事实；
- 重新评 D / E；
- 自己改变 Jev 分类；
- 因叙事需要提升 M；
- 把 association 写成 effect；
- 把机制写成人体功效；
- 把低证据候选写成传统定论。

发现资料不足时：

```text
Writing
→ 返回“整”或“搜”
```

而不是在正文里自行补结论。

### 输出

`entries/<entry-id>.md`

生活场景使用：

`scenes/<scene-id>.md`

## 六、四阶段与内部方法的关系

| 主阶段 | 内部工具 |
|---|---|
| 搜 | Identity、R、Search Log、Evidence Record、D、传统来源、安全检索 |
| 整 | Appraisal、Synthesis、E、Concept Trace、机制解释、冲突/未知、Stop、Reference audit |
| 判 | Jev v0.4、四气/五味/归经/阴阳±、M、mapping record |
| 写 | Claim Ledger、传统习惯词派生、正文结构、引用、写作 QA |

Claim Ledger 是“判 → 写”的交接工具，不是第五个主阶段。

---

## 七、文件接口

推荐一个正式 Entry 使用：

```text
references/entries/<entry-id>/
├── research.md     # 搜：来源、证据与详细研究底稿
├── summary.md      # 整：连续中立说明文档；Jev 正式输入
└── mapping.md      # 判：Jev 分类 + M + 分类依据

entries/
└── <entry-id>.md   # 写：读者正文
```

Research Parent 可继续只维护共享 `research.md`；正式子条生成自己的 `summary.md` 和 `mapping.md`，并重新判断证据距离。

## 八、阶段门

### 搜 → 整

必须：

- 身份稳定；
- 核心来源已收集；
- 直接证据、安全、反证均覆盖到研究预算要求；
- 关键来源可核验。

### 整 → 判

必须：

- Summary Document 可独立阅读；
- E / D 已稳定；
- 冲突、未知和替代解释没有被删掉；
- 未提前写入分类答案；
- evidence cutoff 和停止理由明确。

### 判 → 写

必须：

- Jev schema 完整；
- actual model 已记录；
- 原生 scores / probabilities 已保存；
- M 已逐项附在分类命题上；
- 分类结果没有反向改写 research facts。

### 写 → QA

必须：

- 正文没有新增上游不存在的事实；
- 文字强度符合 E / M；
- 重要 claim 可追溯到 research / summary / mapping；
- 安全、限制与未知没有被为了可读性删除。

---

## 九、生产口令

整个项目以后统一用：

> **搜资料，整资料，Jev 判，按资料和分类写。**

更短：

> **搜 → 整 → 判 → 写。**
