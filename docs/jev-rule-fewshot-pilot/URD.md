# Idea Brief — Jev 四气五味归经规则 + Few-shot Pilot

> 状态：pilot-v0.3.1  
> 文档强度：simple（小型实验）  
> 适用范围：验证 Jev 是否能根据《居家本草》式说明文档，按固定推理规则输出四气、五味、五脏归经。

## 1. 目标用户

- **URD-ROLE-001**：《居家本草》编者 / 研究者。

## 2. 核心任务

- **URD-REQ-001**：把完成检索、综合后形成的自然语言说明文档交给 Jev，由 Jev 按项目固定推理规则判断四气、五味和五脏归经。
- **URD-REQ-002**：采用“推理规则 + five-shot”而不是微调、LoRA 或 post-hoc 概率修正函数。
- **URD-REQ-003**：保留 Jev 原生概率，不对 probability / Noul 做后处理映射。
- **URD-REQ-004**：held-out 与 five-shot 样本分离；待测样本对 Jev 隐藏药名和 gold answer。
- **URD-REQ-005**：输出空间固定：四气为寒/凉/平/温/热；五味为酸/苦/甘/辛/咸；归经为心/肝/脾/肺/肾。
- **URD-REQ-006**：同一冻结配置重复运行，分别保存原生结果，不用投票或均值覆盖单次输出。
- **URD-REQ-007**：state 中的 rules 只描述“如何从说明文档推理”，不重复 question schema 已经保证的输出限制。
- **URD-REQ-008**：target 以连续中文说明文档字符串发送，不要求 `organoleptic_sensory`、`traditional_functions` 等结构化字段。

## 3. 输入契约

Jev 实际 state：

```text
判定方法
+ 5 个自然语言说明文档式参考示例及标准结果
+ 1 个自然语言待判断说明文档
```

说明文档可以包含：

- 感官特征；
- 传统功能；
- 主治 / 症候；
- 功能与脏腑关系的解释；
- 未来现代食品场景中的人体效应、传统理论桥梁等。

但不得直接写出待测对象的四气、五味或归经答案。

## 4. 推理任务

### 四气

先判断说明文档所描述证候的寒热方向，再看药物 / 食物作用是在清热还是散寒、是在一般温散还是回阳救逆，并根据强弱区分寒/凉、温/热；寒热方向不突出时考虑平。

### 五味

同时使用感官和功能模式：

- 辛：散、行、通；
- 苦：清、泻、降、燥；
- 甘：补、和、缓、生；
- 酸：收、涩、生津；
- 咸：软坚、散结、润下。

入口味觉是证据之一，不等于传统五味答案。

### 五脏归经

先把症状 / 功能聚成脏腑功能群，再独立评估心、肝、脾、肺、肾。

由于产品只输出五脏字段，本项目采用工作投影：

- 胆 → 肝胆功能群 → 肝；
- 胃 → 脾胃功能群 → 脾；
- 大肠 → 肺与大肠功能群 → 肺；
- 小肠 → 心与小肠功能群 → 心；
- 膀胱 → 肾与膀胱功能群 → 肾；
- 三焦不固定投影，按具体上中下焦语境判断。

该投影只服务五字段输出，不声称传统理论中六腑归经与五脏归经等同。

## 5. Five-shot

匿名参考样本：

| demo | 实际药物（Jev 不见药名） | 四气 |
|---|---|---|
| V31-D01 | 黄连 | 寒 |
| V31-D02 | 薄荷 | 凉 |
| V31-D03 | 山药 | 平 |
| V31-D04 | 桂枝 | 温 |
| V31-D05 | 附子 | 热 |

每个示例均为连续说明文档 + 标准四气 / 五味 / 五脏归经。

## 6. v0.3.1 Held-out

| sample | 实际药物（仅评分端可见） | 四气 | 五味 | 五脏归经 |
|---|---|---|---|---|
| V31-T01 | 胖大海 | 寒 | 甘 | 肺 |
| V31-T02 | 余甘子 | 凉 | 甘、酸 | 肺、脾 |
| V31-T03 | 黄精 | 平 | 甘 | 脾、肺、肾 |
| V31-T04 | 草豆蔻 | 温 | 辛 | 脾 |
| V31-T05 | 吴茱萸 | 热 | 辛、苦 | 肝、脾、肾 |

选择原则：说明文档本身必须包含足够桥梁，使 gold 能从文本内部合理推出。

## 7. 成功标准

- **URD-AC-001**：5/5 held-out 均成功调用 Jev。
- **URD-AC-002**：保存所有 Choice probabilities / Noul 原始值。
- **URD-AC-003**：state 中没有 held-out 药名、source URL 或 gold。
- **URD-AC-004**：GitHub Actions 从 Environment `API_KEYS` 注入 `JEV_API_KEY`，日志不暴露 secret。
- **URD-AC-005**：自动生成四气 accuracy、五味和五脏归经的 exact set 与 micro P/R/F1。
- **URD-AC-006**：同一冻结配置重复 3 次并报告稳定性。
- **URD-AC-007**：不能因 5 个 reasoning-complete 样本表现好就宣称生产系统“已校准”或准确率已确定。

## 8. 不在本轮范围

- Jev 微调 / 后训练；
- 自建概率校准函数；
- 用 5 个样本确定生产阈值；
- 自动写入正式条目；
- 验证真实现代食品的 domain transfer；
- 改变《居家本草》现有 E / M 分级。

## 9. 约束

- **URD-CON-001**：记录 requested alias 与 actual Jev model。
- **URD-CON-002**：API key 不进入仓库。
- **URD-CON-003**：规则、five-shot、held-out、runner、结果均版本化。
- **URD-CON-004**：任何因错例修改推理规则的实验必须升版本；无效 test-contract bug 可明确标记 invalid 后修正。

## 10. 假设与开放问题

### 已采用假设

- **URD-ASM-001**：Noul 0.5 只用于 pilot 评分转标签，不是生产阈值。
- **URD-ASM-002**：匿名化减少药名记忆泄漏，但不能完全排除模型由症状组合反识别药物。
- **URD-ASM-003**：中药 gold 以公开药典资料为基础，再按本项目五脏功能群投影生成五字段 gold。
- **URD-ASM-004**：说明文档必须和 gold 存在可追踪的内在推理桥梁，否则该样本不适合作为本阶段方法测试。

### 下一阶段问题

- **URD-Q-001**：真实 Research Dossier 直接生成的说明文档是否具有足够桥梁，而无需为了 Jev 特制？
- **URD-Q-002**：现代食品没有传统功效 / 主治时，规则如何把人体效应和 Concept Trace 接入同一推理链？
- **URD-Q-003**：什么时候需要人工复核，以及是否需要设概率区间？应由后续真实食品样本决定。
