# Idea Brief — Jev 四气五味归经规则 + Few-shot Pilot

> 状态：pilot-v0.1  
> 文档强度：simple（小型实验）  
> 适用范围：仅验证 Jev 判定流程，不改变《居家本草》现有 E / M 规则。

## 1. 目标用户

- **URD-ROLE-001**：《居家本草》编者 / 研究者。

## 2. 核心任务

- **URD-REQ-001**：把已经完成检索与整理的资料包交给 Jev，由 Jev 按固定规则输出四气、五味、归经的结构化概率判断。
- **URD-REQ-002**：采用“规则 + few-shot”而不是微调、LoRA、Platt scaling、isotonic regression 等模型或概率修正方法。
- **URD-REQ-003**：保留 Jev 原生概率，不对概率做后处理映射；pilot 评分时仅用 0.5 作为 Noul 的临时二值切分点。
- **URD-REQ-004**：测试样本必须与 few-shot 示例分离；测试样本对 Jev 隐藏药名和 gold answer。
- **URD-REQ-005**：允许“不足以判断”。四气使用显式“证据不足”选项；五味与归经用接近 0.5 的 Noul 表达不确定。
- **URD-REQ-006**：评估阶段记录同一冻结配置的重复运行稳定性；不同 run 的原生结果分别保存，不用投票或平均值覆盖原始输出。

## 3. Pilot 样本

### Held-out 测试样本（5 味）

| sample_id | 实际药物（仅 gold 文件可见） | 四气覆盖目的 |
|---|---|---|
| T01 | 黄连 | 寒 |
| T02 | 薄荷 | 凉 |
| T03 | 山药 | 平 |
| T04 | 桂枝 | 温 |
| T05 | 附子 | 热（药典“大热”归一） |

### Few-shot 参考样本

使用与测试集不同的 4 个匿名参考样本，来源于肉桂、五味子、葶苈子、苏木。它们用于展示规则边界，不计入测试成绩。

## 4. 四气归一规则

pilot 只输出五档：

| 输出 | 吸收的传统表述 |
|---|---|
| 寒 | 大寒、寒 |
| 凉 | 凉、微寒 |
| 平 | 平 |
| 温 | 微温、温 |
| 热 | 热、大热 |

此归一仅用于工程测试，不宣称解决传统术语史或所有教材差异。

## 5. 五味与归经输出

### 五味

分别使用 5 个独立 Noul：

- 酸
- 苦
- 甘
- 辛
- 咸

每味可同时为多个标签。pilot 暂不把“淡、涩”纳入正式输出；若后续项目需要，另开设计变更。

### 归经

分别使用 12 个独立 Noul：

- 心、肝、脾、肺、肾
- 胆、胃、大肠、小肠、膀胱
- 三焦、心包

每经独立判断，不要求概率和为 1。

## 6. Evidence Packet 边界

测试 Jev 时的 target packet：

- 保留：感官描述、传统功能、传统主治、必要的加工信息；
- 删除：药名、拼音、拉丁名、原植物名等可直接识别身份的字段；
- 删除：任何直接写出的“性味”“归经”答案；
- gold answer 单独存放，runner 构造 API state 时不得发送 gold。

本轮是**技术可行性 pilot**，使用权威药典条目的“去标签版”资料，不等同于正式条目的完整 Research Dossier。若本轮有价值，下一轮再用项目完整检索工作流生成 calibration dossier。

## 7. 成功标准

- **URD-AC-001**：5 个 held-out 样本均成功调用 Jev 并返回可解析结果。
- **URD-AC-002**：输出保存 Jev 原生 choice probabilities / Noul probabilities。
- **URD-AC-003**：target 请求中不包含 gold 字段和测试药物名称。
- **URD-AC-004**：GitHub Actions 从 Environment `API_KEYS` 读取 `JEV_API_KEY`，日志不暴露 secret。
- **URD-AC-005**：自动生成四气准确数、五味与归经的 set / micro 指标，供人工判断是否值得扩大样本。
- **URD-AC-006**：本 pilot 不以 5 个样本设生产阈值，也不因小样本结果宣称“已校准”。
- **URD-AC-007**：同一 prompt / fixtures 的重复运行若产生差异，必须作为稳定性结果报告，不得挑选最好的一次代表模型表现。

## 8. 不在本轮范围

- 模型微调或后训练；
- 概率校准函数；
- 根据 5 个样本确定正式接受阈值；
- 自动写入正式条目；
- 用 Jev 替代 Research Dossier 的资料检索和证据综合；
- 正式解决“淡、涩、微寒、微温”等全书术语规范。

## 9. 约束

- **URD-CON-001**：固定记录实际 Jev model 版本。
- **URD-CON-002**：API key 只存在 GitHub Environment Secret，不写入仓库。
- **URD-CON-003**：结果文件不得包含 secret。
- **URD-CON-004**：规则、few-shot、fixtures 与评分代码必须版本化，保证后续可以复跑。

## 10. 假设与开放问题

### 已采用假设

- **URD-ASM-001**：0.5 仅作为 pilot 中 Noul 转标签的评分切点，不是生产置信阈值。
- **URD-ASM-002**：匿名化能减少“看到药名直接背答案”的影响，但不能完全消除模型从症状组合反识别药物的可能。
- **URD-ASM-003**：本轮 gold 以《中国药典 2025 年版》条目所载性味归经为准。
- **URD-ASM-004**：Jev 同一输入可能出现小幅概率波动，因此单次 run 不能代表稳定性；重复运行仅用于测量波动，不属于概率修正函数。

### 后续开放问题

- **URD-Q-001**：正式食品推演时，五味是否加入“淡、涩”扩展标签？
- **URD-Q-002**：完整 Research Dossier 输入后，是否需要为“传统直接记载”和“现代拟映射”分开两个 Jev 任务？
- **URD-Q-003**：生产环境应使用何种人工复核阈值？需在更大 calibration set 上决定。
- **URD-Q-004**：正式评估每个冻结配置需要重复几次？v0.1 暂以 3 次重复观察稳定性，后续按成本与方差决定。
