## 8. 核心发现

### 8.1 v0.3.1 能迁移“性味方向”，但强制四气必须谨慎消费

五个食品四气三次都稳定：

- 开心果：温；
- 其余四项：平。

其中开心果、咖啡有一定历史/近现代资料背景可作对照。

但黑巧克力、酸奶、方便面的“平”不能因为 Jev 被强制 Choice 就自动进入正式 Materia mapping。

这意味着生产系统必须区分：

```text
Jev forced classification
vs
项目证据等级允许公开写出的结论
```

### 8.2 最大问题是“功能对应 → 归经”的门槛

本轮三个诊断点：

```text
开心果：
调中 / 诸痢 / 腰冷
→ Jev 脾 0.71、肾 0.75
→ dossier 仍要求 M-0

咖啡：
健胃
→ Jev 脾 ≈0.50
→ dossier M-0

酸奶：
消化耐受 / 发酵
→ Jev 脾 ≈0.60
→ dossier 健脾仅 M-IV，归经 M-0
```

因此当前 v0.3.1 reasoning rules **缺少 M-level gate**。

它教会 Jev “什么症状属于什么脏腑功能群”，但没有教：

> “功能群相关”与“足以拟定归经”是两个不同门槛。

### 8.3 负面 / 边界信息非常重要

方便面说明文档明确保留：

- 高盐口渴可以由钠 / 渗透压解释；
- 热汤只是 serving temperature；
- 油炸 / 辣味依产品而变。

Jev 因而没有机械判：

- 咸；
- 热；
- 脾。

说明未来 Research Dossier 转说明文档时，**替代解释、冲突与边界本身必须保留**，不能只摘“支持映射”的段落。

### 8.4 不需要概率修正函数

这次问题不是：

> 0.71 应该数学修正成 0.42。

而是：

> “调中 / 腰冷”到底在什么证据等级下允许从功能相关升级成归经？

这是 reasoning / evidence-policy 问题。

继续坚持“不训练 post-hoc correction function”是合理的。

## 9. 对下一版 rules 的要求

本轮先冻结，不在同一测试集上修改后重新报分。

若建立 domain-transfer v0.2，最关键的新增规则应不是更多脏腑症状词，而是 **证据门槛**：

```text
第一层：功能群相关
  例如 呕吐吞酸 -> 脾胃相关
  腰冷 / 肾虚表现 -> 肾系相关

第二层：归经候选
  只有功能群相关还不够。
  需要传统明确归经、直接证候人体证据，
  或至少达到项目 M-II 所需的稳定临床功能对应 + 理论桥梁。

第三层：归经输出
  若仅为 M-III / M-IV 类比，归经 Noul 应保持低值，
  不因为症状词面相关直接升高。
```

也就是说：

> **先判断“它作用到哪里”，再判断“这种证据够不够叫归经”。**

这是本轮 domain transfer 得到的最重要规则缺口。

## 10. 结论

v0.3.1 并没有在现代食品上失效。

它已经表现出：

- 能稳定读取自然语言 dossier；
- 能保留一些传统 / 近现代性味方向；
- 能在黑巧克力、方便面这类证据弱对象上不乱归经；
- 能利用说明文档中的反证和替代解释。

但它对“脾胃 / 肾系功能相关”到“归经”的升级过快。

因此下一轮优先任务不是扩更多症状字典，也不是数学校准，而是把《居家本草》现有 **M-I～M-0 的证据门槛正式写进 Jev reasoning rules**。
