Gold：

- 四气：寒
- 五味：苦
- 归经：心、脾、胃、肝、胆、大肠

预测：

- 四气：寒，P=1.00
- 五味：苦 0.96

- 四气正确

观察：大肠 0.46、三焦 0.47 都处于边界区；硬用 0.5 会把非常接近的判断切成不同标签。

## 3. 这次 pilot 能说明什么

### 3.1 规则 + few-shot 路线值得继续

工程链已经跑通：

```text
masked evidence packet
+ project rules
+ 4 few-shot demonstrations
-> Jev
-> native probabilities
-> gold comparison
```

没有模型微调，也没有概率修正函数。

### 3.2 四气目前最稳定，但不能高估 5/5

本轮资料里存在很强的寒热线索：

- 清热 / 泻火；
- 清凉；
- 温通 / 风寒；
- 回阳 / 补火 / 散寒。

因此 5/5 说明 Jev 能使用这些线索，不说明面对现代食品的完整 dossier 也能达到同样表现。

### 3.3 五味的核心问题是“感官味觉”和“传统五味”混淆

附子是最有价值的反例：

```text
感官：咸麻 / 味淡
gold：辛、甘
Jev：辛、咸
```

下一版应该把 packet 明确拆成：

```yaml
organoleptic_sensory:
traditional_functional_evidence:
modern_human_evidence:
mechanism:
```

并在规则中明确：`organoleptic_sensory` 不能单独决定传统五味。

### 3.4 归经是当前主要难点

归经 exact set 只有 1/5，即使 micro-F1 有 0.824，也不能把总体数字理解成“归经已经可用”。

主要错误模式：

1. **功能词直接升格为归经**：山药“养胃” -> 假阳性胃经；
2. **相邻合理解释竞争**：桂枝肺 / 膀胱略低于 0.5，同时肾略高于 0.5；
3. **广泛归经漏一条**：黄连大肠 0.46。

这与《居家本草》现有规则一致：功效 / 现代器官功能不能直接等同于归经。

### 3.5 同输入存在小幅随机波动

意外的 docs-only 重跑暴露了一个有价值的事实：同一冻结输入并非严格确定性。当前波动主要出现在 0.5 左右，尚未观察到高概率四气标签翻转。

因此后续 benchmark 应把“重复运行稳定性”列为正式指标，但这与训练校准函数是两回事：我们仍保留每次 Jev 原生概率，不制造一个新的校准概率。

## 4. 关于“是否需要校准函数”

本轮没有显示出“必须训练一个修正函数”的理由。

当前错误首先来自：

- packet 字段没有充分区分感官与传统属性；
- 归经的规则仍允许词面捷径；
- 0.5 附近的大量结果本来就表达不确定。

因此下一步优先顺序应是：

1. 改进 packet schema；
2. 改进 rule + contrastive few-shot；
3. 扩大独立 held-out 样本；
4. 最后才讨论接受 / 复核阈值。

不建议现在加入概率变换函数。

## 5. 下一版 v0.2 建议

### 规则修改

新增两条硬规则：

> “某功能或主治出现脾、胃、肺、肾等脏腑词，只能形成候选，不足以单独判定归该经。”

> “入口感官味觉只是一类证据；若感官味与传统功能模式冲突，不得自动把感官词作为五味标签。”

### Few-shot 修改

增加两类 contrastive example：

1. **出现‘养胃’但 gold 不归胃经**的例子；
2. **入口有咸味但传统五味不含咸**的例子。

这样比增加大量普通正例更能针对当前错误。

### 输出策略

仍保留 Jev 原生概率，不训练修正函数。

后续 calibration set 足够大前，不把 0.5 当生产阈值。评估冻结版本时建议至少做少量重复运行，观察边界标签是否翻转；生产是否需要重复调用另行决定。可以保留：

```text
high positive
uncertain / review
high negative
```

三段式人工流程，但具体边界必须由更大样本决定。

## 6. API / workflow 发现

当前账号的 `GET /v1/models` 暴露：

- `jev-latest`
- `jev-preview`

不能直接请求 `jev-1.13.0`。本次使用 `jev-latest`，API 实际返回 `jev-1.13.0`。

因此复现策略应是：

- request 中保存 alias；
- results 中保存 actual model；
- actual model 变化后视为新的实验条件，不与旧 run 无区分混合。

## 7. 结论

**工程可行性：通过。**

规则 + few-shot 可以直接用于 Jev，不需要 GPU，也不需要自建校准函数。  
但当前 5 味 pilot 只足以支持继续研究，不足以把归经判断接入正式条目。

下一轮最值得做的是 **v0.2 规则 / packet schema 修订 + 更大的独立中药 held-out set**，然后再用完整《居家本草》Research Dossier 做现代食品外域测试。
