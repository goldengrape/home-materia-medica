# Jev v0.4 Design — 五脏定位 + 阴阳增减主方向

> 状态：implementation / regression
> 决策：**语义上级连，计算上同步**
> 基线：v0.3.1 的四气、五味、五脏归经保留。

## 1. 底层分类

传统功能词下沉为派生表达。

Jev 一级输出只保留：

1. 四气；
2. 五味；
3. 五脏归经；
4. 每个五脏归经的阴阳增减主方向。

底层表示：

```text
位置：心 / 肝 / 脾 / 肺 / 肾
方向：阴- / 阴+ / 阳- / 阳+
```

例如：

```text
肝 + 阳-
→ 后续可写成“疏肝”等习惯用词
```

习惯用词不再作为一级 ontology。

## 2. 级连还是同步

### 语义上级连

```text
说明文档
→ 先判断作用位置（归经）
→ 再判断该位置的阴阳增减主方向
```

### 计算上同步

两层在同一次 Jev request 中完成，不做两次 API 调用。

原因：

- 避免第一层漏经后第二层永远无法判断；
- 避免 0.49 / 0.51 之类阈值波动改变第二次 question schema；
- 同一证据常同时提供位置和方向；
- 降低重复发送说明文档的成本。

## 3. 输出 questions

### 四气

1 个 Choice：

```text
寒 / 凉 / 平 / 温 / 热
```

### 五味

5 个独立 Noul：

```text
酸 / 苦 / 甘 / 辛 / 咸
```

### 五脏归经

5 个独立 Noul：

```text
心 / 肝 / 脾 / 肺 / 肾
```

### 每经主方向

5 个 Choice：

```text
heart_direction
liver_direction
spleen_direction
lung_direction
kidney_direction
```

每个 Choice 的备选固定为：

```text
阴-
阴+
阳-
阳+
```

总 question 数：**16**。

## 4. 为什么主方向用 Choice

前一 draft 曾把 20 个方向全部做成独立 Noul。实际回归发现，这会自然产生同一经多个方向同时过阈值，虽然有信息量，但偏离“先做原子分类，再附加传统用词”的目标。

v0.4 改成：

> 每个归经输出一个“主方向 Choice”，同时保存四个 Choice probabilities。

因此如果某经同时存在两个方向，例如：

```text
肺阴+ 0.55
肺阳- 0.40
```

研究层仍能看到次方向，但主分类保持单一：

```text
肺：阴+
```

未来若确实需要多方向输出，可从 Choice probability 分布派生，而不在一级 schema 中制造 20 个布尔标签。

## 5. 四个方向的项目工作语义

### 阳+

增加该经温煦、推动、活动、运化或其他功能性阳侧表现。

典型：

- 温；
- 助阳；
- 回阳；
- 健脾 / 健胃 / 助运；
- 对寒、虚寒、功能低下的纠偏。

### 阳-

减少该经热、火、亢进、升越或过强活动。

典型：

- 清热；
- 泻火；
- 平亢；
- 对热盛、火盛、亢奋的纠偏；
- 项目工作约定：疏肝 → 肝阳-。

### 阴+

增加该经滋养、津液、血、精、濡润、收摄等阴侧表现。

典型：

- 养阴；
- 生津；
- 润燥 / 润肺 / 润肠；
- 补血；
- 益精；
- 对津亏、阴虚、燥、精血不足的纠偏。

### 阴-

减少该经阴侧偏盛、停聚、积滞或壅滞。

典型：

- 化湿；
- 燥湿；
- 化痰；
- 利水；
- 消食 / 消积；
- 对寒湿、水停、痰湿、食积的纠偏。

## 6. + / - 不是好坏或副作用

```text
阴- != 伤阴
阳- != 损阳
阴+ != 滋腻
阳+ != 上火
```

+ / - 只描述这味食材对相应功能轴的主要作用方向。

安全性、副作用和过量效应另行记录。

## 7. 必须区分原始病机与食材作用

例如：

```text
心火亢盛
= 被处理的状态偏心阳过盛

清心泻火
= 食材作用方向为心阳-
```

不能因为文本里有“心火亢盛”就判成心阳+。

同理：

```text
肾阳虚 + 补火助阳 → 肾阳+
肺燥 + 润肺生津 → 肺阴+
痰湿 + 化痰燥湿 → 相应功能域阴-
```

## 8. 方向 Choice 如何使用归经

五个 direction Choice 在同一次 request 中全部计算。

但研究层只把方向解释为正式候选，当对应归经本身值得展示时。

例如：

```yaml
肝:
  meridian_score: 0.82
  direction:
    choice: 阳-
    probabilities:
      阴-: 0.10
      阴+: 0.12
      阳-: 0.70
      阳+: 0.08
```

如果肝经 score 很低，仍保存 direction 原始分布，但不把它单独写成“肝阳-”结论。

## 9. 与四气、五味的关系

四层互相独立：

```text
四气 = 全局寒热属性
五味 = 全局功能模式
归经 = 作用位置
阴阳± = 该位置上的主作用方向
```

不能用其中一层机械推出另一层。

## 10. 传统用词的派生层

后期单独维护：

```text
primitive classification
→ conventional wording
```

例如：

```text
肝 + 阳- → 疏肝 / 平肝等候选词
脾 + 阳+ → 健脾 / 温中等候选词
肺 + 阴+ → 润肺 / 生津等候选词
脾 + 阴- → 化湿 / 消食等候选词
```

具体用哪个词仍由语境决定，不做一对一硬翻译。

## 11. Jev score 与 M grade

继续保持：

```text
Jev score != M grade
```

方向 Choice probability 也是 Jev 原生判断分布，不是证据等级。

例如：

```text
脾：0.61｜M-0
主方向：阳+ 0.68｜M-IV
```

可以成立。

## 12. 当前验证策略

v0.4 暂不替换 main 的 v0.3.1。

先验证：

1. 已知中药能否稳定得到正确位置 + 主方向；
2. 主方向 probabilities 是否能合理反映混合效应；
3. 加入方向 Choice 后，是否破坏原有四气 / 五味 / 归经表现；
4. 再做现代食品 domain-transfer。
