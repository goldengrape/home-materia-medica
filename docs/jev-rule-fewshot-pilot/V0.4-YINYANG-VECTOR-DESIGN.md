# Jev v0.4 Design — 五脏定位 + 阴阳增减向量

> 状态：draft
> 决策：**语义上分层，计算上同步**
> 基线：Jev v0.3.1 的四气 / 五味 / 五脏归经保留。

## 1. 为什么增加阴阳增减

原先“疏肝、健脾、安神、润燥、清热、温中、化湿、生津”等词容易同时承担：

- 作用位置；
- 阴阳方向；
- 补 / 泄方向；
- 历史习惯命名。

v0.4 将底层分类拆成更少、更稳定的原子变量：

1. **位置**：心 / 肝 / 脾 / 肺 / 肾；
2. **方向**：阴- / 阴+ / 阳- / 阳+。

传统习惯用词作为后续派生层，不再作为 Jev 的一级输出。

例如按项目工作约定：

```text
肝 + 阳-
→ 可派生为“疏肝”等习惯表达
```

派生词不反向改变 Jev 原始分类。

## 2. 语义分层，计算同步

### 语义层

```text
说明文档
→ 归经定位
→ 该经阴阳增减方向
→ 后续习惯术语
```

### 计算层

一次 Jev request 同时判断：

- 四气；
- 五味；
- 五脏归经；
- 五脏各自的四个阴阳方向。

不做：

```text
Call 1: 先判归经
↓ threshold
Call 2: 只对通过 threshold 的经判阴阳方向
```

## 3. 为什么不采用 API 级连

级连会引入：

1. **误差传递**：第一层漏掉某经，第二层永远没有机会判断该经方向；
2. **阈值敏感**：例如脾 score 0.49 / 0.51 会导致第二次调用结构不同；
3. **随机性放大**：第一次调用的边界波动会改变第二次问题集合；
4. **证据被拆开**：例如“心火亢盛 + 清心泻火”本来同时说明心和心阳-；
5. **调用成本增加**：同一说明文档需要重复发送。

因此推理保持一层 request。

保留：

- 1 个四气 Choice；

- 20 个经脏阴阳方向 Noul。

## 5. 为什么四方向是独立 Noul

不使用一个四选一 Choice。

原因是同一食材在同一经可以同时支持多个方向，例如：

- 阴+ 与阳- 可以同时存在；
- 阴+ 与阳+ 可以同时存在；
- 不同剂量 / 人群 /证候下也可能出现方向差异。

所以：

```text
心阴-
心阴+
心阳-
心阳+
```

四项分别保存原生 score，不强迫互斥。

## 6. 四个方向的项目工作语义

这些是《居家本草》的计算工作轴，不声称等同所有传统术语。

### 阳+

增加该经的温煦、推动、活动或功能性阳侧表现。

常见证据方向：

- 温；
- 助阳；
- 回阳；
- 振奋；
- 推动功能；
- 对寒、虚寒、功能低下的纠偏。

### 阳-

减少该经的热、火、亢进、升越或过强活动。

常见证据方向：

- 清热；
- 泻火；
- 平亢；
- 降逆；
- 对热盛、火盛、亢奋的纠偏。

项目约定示例：

```text
疏肝 → 肝阳-（作为派生词规则，而非 Jev 一级标签）
```

### 阴+

增加该经的滋养、津液、血、精、濡润、收摄等阴侧表现。

常见证据方向：

- 养阴；
- 生津；
- 润燥；
- 补血 / 益精；
- 对阴液不足、燥、虚损的纠偏。

### 阴-

减少该经的阴侧壅滞、停聚或偏盛。

在本项目中首先用于描述：

- 湿；
- 痰；
- 水停；
- 寒湿；
- 其他可被理解为阴侧偏盛 / 停聚的对象被化、燥、利、泄。

**阴- 不等于“伤阴”。**

它表示“减少阴侧偏盛 / 停聚”的作用方向；是否存在损伤正常阴液属于另一安全 / 副作用命题。

## 7. 必须区分病机状态与食材作用方向

这是 v0.4 最重要的 reasoning rule。

例如：

```text
心火亢盛
= 被处理的状态偏“心阳+ / 火盛”

清心泻火
= 食材 / 药物的作用方向是“心阳-”
```

不能看到“心火亢盛”就把食材判成心阳+。

同理：

```text
肾阳虚、腰冷
+ 补火助阳
→ 肾阳+

肺燥、口干
+ 润肺生津
→ 肺阴+

痰湿壅盛
+ 化痰燥湿
→ 对相应功能域的阴-
```

推理顺序：

1. 识别被处理的失衡状态；
2. 识别说明文档描述的实际干预 / 食材作用；
3. 输出“食材使该经哪个方向增加或减少”。

## 8. 归经与方向的关系

归经是“位置 score”。

阴阳±是“位置 + 方向 score”。

例如：

```yaml
肝:
  meridian: 0.82
  yin_minus: 0.12
  yin_plus: 0.18
  yang_minus: 0.76
  yang_plus: 0.09
```

研究层保存全部值。

若出现：

```text
meridian_liver < 0.5
但 liver_yang_decrease >= 0.5
```

不自动修改任一分数，记录为 **location-direction disagreement**，供 QA 检查。

## 9. 推理同步，展示可级连

模型一次同时输出全部 score。

读者层可以按归经组织：

```text
肝：0.82
  阳-：0.76
  阴+：0.18
  阴-：0.12
  阳+：0.09

心：0.63
  阳+：0.71
  ...
```

也可以只展开主要归经的方向，低归经 score 的方向折叠。

但原始记录不得删除。

## 10. 习惯术语成为派生层

未来单独维护：

```text
primitive vector
→ conventional wording
```

例如：

```text
肝 + 阳- → 疏肝（项目工作映射之一）
脾 + 阳+ → 可映射到温中 / 健运类词
肺 + 阴+ → 可映射到润肺 / 生津类词
```

同一向量可以对应多个传统词；具体用词还要看说明文档语境。

因此不建议现在为“疏肝、健脾、安神、润燥、清热、温中、化湿、生津”分别建立一级 Concept ontology。

更小的基础概念骨架应优先定义：

- 四气；
- 五味；
- 心 / 肝 / 脾 / 肺 / 肾；
- 阴 / 阳；
- + / - 的项目工作语义；
- 传统习惯词的派生规则。

## 11. 与 M grade 的关系

不变：

```text
Jev score != M grade
```

例如：

```text
脾：0.61｜M-0
脾阳+：0.68｜M-IV
```

是允许的。

M 不压低 Jev score；
Jev score 也不提升 M。

## 12. 下一步验证

v0.4 不直接替换 v0.3.1 production baseline。

先做：

1. 为少量已知中药补充“归经 + 阴阳±”人工 gold；
2. 检查同步 question 是否产生 location-direction disagreement；
3. 再用现有食品 domain-transfer 样本看新方向输出是否合理；
4. 通过后再把 v0.4 升为 skill 当前版本。
