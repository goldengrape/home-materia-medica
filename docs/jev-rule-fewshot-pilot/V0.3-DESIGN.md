# v0.3 Design — 文档输入 + 推理规则 + Five-shot

> 后续修正：见 `V0.3.1-DESIGN-CORRECTION.md`。v0.3 #11 因 gold 投影与样本说明一致性问题不作为有效 benchmark。

> 状态：superseded by v0.3.1；Actions #11 仅作 design-check
> 基线：v0.2 的封闭 question schema 保留；重做 state / prompt 语义。
> 原因：v0.2 把接口约束写进 rules，并把 target 人工拆成结构化 packet，与未来真实 Research Dossier / 说明文档输入不一致。

## 1. 核心改变

### DEC-011｜rules 只描述“如何推理”

Jev 的 question type / criteria 已经限定输出空间，state 中不再重复：

- 必须五选一；
- 只能输出哪些字段；
- 没有 abstention；
- schema 外字段不存在。

这些属于接口契约，不属于推理知识。

v0.3 rules 的职责只有一个：

> 教 Jev 如何从说明文档里的感官、传统功能、主治和症候关系，逐步推断四气、五味、五脏归经。

### DEC-012｜target 是自然语言说明文档

实际 state 中的 target 不再是：

```json
{
  "organoleptic_sensory": [],
  "traditional_functions": [],
  "traditional_indications": []
}
```

而是一个连续的中文说明文档。例如：

```text
本品为……。气微，味……。传统使用中以……为主要功能，常用于……。
这些表现主要涉及……，并可见……。
```

未来可直接替换成《居家本草》完成检索后形成的说明文档；runner 不要求固定字段。

### DEC-013｜few-shot 也使用说明文档

five-shot 每个示例由：

```text
说明文档
→ 标准四气
→ 标准五味
→ 标准五脏归经
```

组成。

药名仍不发送给 Jev，避免把“背过某味药”误当成从资料推断。

## 2. 推理链

### 2.1 先理解资料，不做关键词直译

通读说明文档，先回答：

1. 资料描述的主要病机 / 功能方向是什么？
2. 症状集中在哪些脏腑功能群？
3. 治疗方向主要是在清热、散寒、补益、收敛、行散、降逆、利湿、化痰，还是其他？
4. 感官味觉与功能方向是否一致？
5. 同一方向是否有多个相互独立的线索重复支持？

单个词只能形成线索，不能自动成为最终标签。

### 2.2 四气

先看“所针对的证候冷热”，再看“功能采取的纠偏方向”。

#### 寒 / 凉方向

以下组合支持寒凉：

- 清热、泻火、凉血、解毒、除烦；
- 高热、烦渴、血热、火毒、湿热、目赤等热象；
- 风热、咽喉红肿、头目红赤等偏表 / 偏轻热象。

工作区分：

- 深、盛、强的里热 / 火热证据反复出现，如高热、火毒、血热、湿热内盛 → 更偏“寒”；
- 较轻、偏表、偏疏散的风热 / 头目咽喉热象 → 更偏“凉”。

#### 温 / 热方向

以下组合支持温热：

- 散寒、温中、温经、温肺、助阳、回阳；
- 冷痛、肢冷、寒饮、寒湿、五更泄泻、阳虚等寒象。

工作区分：

- 解表散寒、一般温中、温肺、温通 → 更偏“温”；
- 回阳、助阳、救逆、明显阳虚寒盛、强烈寒凝冷痛、五更泄泻等深寒表现 → 更偏“热”。

#### 平

当资料以补益、调和、利水、健运等为主，寒热纠偏方向不突出，且没有持续的强寒 / 强热线索时，更偏“平”。

感官上的清凉、辛辣、温热感可辅助，但不能覆盖传统功能和主治形成的整体方向。

### 2.3 五味

五味同时参考感官和功能模式。感官是直接线索，但传统五味并不等同于入口味觉。

工作映射：

- **辛**：发散、解表、行气、活血、通窍、温通；资料常见“散、行、通”的功能方向。
- **苦**：清泄、泻火、燥湿、降逆、泄降；资料常见“清、泻、降、燥”的方向。
- **甘**：补益、和中、缓急、调和、生津；资料常见“补、和、缓、生”的方向。
- **酸**：收敛、固涩、生津、敛汗、止泻等“收”的方向。
- **咸**：软坚、散结、润下、泻下等方向。

判定时：

1. 感官味和功能方向一致 → 相互加强；
2. 感官味与功能方向不一致 → 不按字面味觉机械赋值；
3. 一个材料可同时有多个味。

### 2.4 五脏归经

先把症状和功能归入“功能群”，再评估心、肝、脾、肺、肾分别得到多少支持。

#### 心

支持线索包括：

- 心悸、怔忡、胸痹心痛；
- 心烦、不寐、神志异常；
- 与血脉、心火、心阳明显相关的描述。

例：`心火亢盛 / 心烦不寐 / 心悸不宁` 是一组相互加强的心系证据。

#### 肝

支持线索包括：

- 胸胁胀痛、情志郁滞；
- 月经、经行腹痛等疏泄 / 冲任相关表现；
- 目系、眩晕、筋脉；
- 黄疸、胆腑湿热等肝胆功能群；
- 厥阴相关描述。

例：`黄疸` 可形成肝胆湿热方向的肝系支持，但应与全文其他证据共同判断。

#### 脾

支持线索包括：

- 食少、腹胀、便溏、泄泻；
- 呕吐、吞酸、脘腹不适等中焦脾胃功能群；
- 湿浊中阻、运化失常；
- 中气下陷、升举无力。

例：`呕吐 / 吞酸 / 脘腹` 先识别为中焦脾胃问题，再作为脾系支持，而不是因为文本中是否出现“脾”字。

#### 肺

支持线索包括：

- 咳嗽、喘、痰、胸闷；
- 鼻、咽喉、声音；
- 外感表证、宣发肃降；
- 肺热、肺寒、肺燥等明确肺系表现。

#### 肾

支持线索包括：

- 腰膝、骨、生殖；
- 遗精、尿频、小便异常；
- 水肿、水液代谢；
- 阳痿、宫冷、肾阳虚；
- 五更泄泻；
- 肾不纳气一类喘证。

### 2.5 同一症状可以承担不同推理作用

不要把“症状 → 一个归经”写成查表。

例如：

- `目赤`、`牙痛` 首先提示火热 / 阳亢，可以增强寒凉判断；是否支持某一脏，还要看上下文。
- `呕吐吞酸` 可支持中焦脾胃功能群，同时若与寒象 / 热象并见，也参与四气判断。
- `黄疸` 可支持肝胆功能群；若明确为湿热黄疸，也同时增强寒凉方向。
- `肢冷脉微` 既是强寒 / 阳虚证据，也可结合回阳、心阳、肾阳等上下文判断五脏。

## 3. v0.3 Five-shot

沿用 v0.2 的 5 个已知标准样本作为 demonstrations，但把资料改写成连续说明文档：

- 黄连：寒；
- 薄荷：凉；
- 山药：平；
- 桂枝：温；
- 附子：热。

示例中不发送药名。

## 4. v0.3 新 held-out

避免继续在 v0.2 五题上调 prompt。新测试集：

所有 target 都以说明文档字符串发送，不发送药名和 gold。

## 5. v0.3 评估

保留 v0.2 的封闭 question schema：

- 四气：Choice；
- 五味：5 个 Noul；
- 五脏归经：5 个 Noul。

但 state 不再包含输出 schema 说明或强制分类说明。

同一冻结版本重复 3 次；保存 Jev 原生概率，不做投票、平均或概率修正。

## 6. Stop / version rule

v0.3 run 后不根据同一 5 个 held-out 继续修改并仍称 v0.3。

若根据 v0.3 错例继续调整推理链，应升 v0.4 并更换 held-out。
