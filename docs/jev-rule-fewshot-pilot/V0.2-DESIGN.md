# v0.2 Design Delta — Jev 封闭字段分类

> 状态：implemented + tested（Actions #8）
> 基线：v0.1 仅保留工程记录；v0.2 修正输出空间设计。
> 对应：URD-REQ-001/002/003/004/006，ADD-DP-001~006，TDD-TEST-001~009。

## 1. v0.2 核心更正

### DEC-007｜三类输出全部是封闭字段

Jev 不负责自由生成“可能的四气五味归经”，而是在预先定义好的 JSON 输出空间内强制分类。

#### 四气

唯一允许的 Choice：

```text
寒
凉
平
温
热
```

- 不设“证据不足”。
- 每个样本必须五选一。
- 传统“大寒/寒”投影到“寒”，“凉/微寒”投影到“凉”，“微温/温”投影到“温”，“热/大热”投影到“热”。

#### 五味

唯一允许的 5 个字段：

```text
酸
苦
甘
辛
咸
```

每个字段独立输出 Noul 概率。不存在“淡”“涩”等输出字段；若 gold 来源含这些标签，v0.2 评分时忽略超出 schema 的标签。

#### 归经

唯一允许的 5 个字段：

```text
心
肝
脾
肺
肾
```

每个字段独立输出 Noul 概率。不存在胃、胆、大肠、小肠、膀胱、三焦、心包等输出字段；若 gold 来源含这些标签，v0.2 评分时忽略超出 schema 的标签。

### DEC-008｜强制分类，不做 abstention

- 四气：Jev 必须返回五选一 Choice。
- 五味、归经：每个固定字段都必须返回 0–1 Noul。
- 不设置“证据不足”“未知”“其他”。
- 0.5 仍只作为 pilot 评分时把 Noul 转为 true/false 的临时切点，不是概率校准。

### DEC-009｜Evidence Packet 分层

target 与 few-shot 的 packet 统一使用：

```yaml
form:
organoleptic_sensory:
traditional_functions:
traditional_indications:
processing_context:
safety_context:
```

其中：

- `organoleptic_sensory` 是真实感官描述，不等于传统五味；
- `traditional_functions` / `traditional_indications` 是主要传统映射证据；
- 空字段允许为空数组；
- 药名、性味、归经 gold 不进入 target state。

### DEC-010｜v0.2 用新的 held-out set

v0.2 不再用黄连、薄荷、山药、桂枝、附子做测试；它们改为 five-shot demonstrations，分别覆盖寒、凉、平、温、热。

新的 held-out：

| sample_id | 药物（仅 gold 可见） | 归一四气 | 五味 schema gold | 五脏归经 schema gold |
|---|---|---|---|---|
| V2-T01 | 黄芩 | 寒 | 苦 | 肺、脾 |
| V2-T02 | 菊花 | 凉 | 甘、苦 | 肺、肝 |
| V2-T03 | 茯苓 | 平 | 甘 | 心、肺、脾、肾 |
| V2-T04 | 细辛 | 温 | 辛 | 心、肺、肾 |
| V2-T05 | 干姜 | 热 | 辛 | 心、肺、脾、肾 |

说明：

- 菊花“微寒”按 v0.2 归一为“凉”；
- 茯苓原 gold 含“淡”，schema 无此字段，因此只评分“甘”；
- 黄芩、干姜原归经含非五脏经，schema 无这些字段，因此仅评分心肝脾肺肾投影。

## 2. v0.2 Few-shot

5 个 demonstrations：

- D01 黄连 → 寒
- D02 薄荷 → 凉
- D03 山药 → 平
- D04 桂枝 → 温
- D05 附子 → 热

全部采用相同封闭 schema。

附子 demonstration 特别用于展示：

```text
organoleptic_sensory 可出现“咸麻”
但固定五味 gold 仍为 辛 + 甘，咸=false
```

从数据结构上告诉 Jev“感官词不自动等于传统五味”。

## 3. v0.2 Test Oracles

### TDD-TEST-010｜输出 key 精确匹配

每个 response 的 answers 必须且只能包含：

```text
qi
taste_sour
taste_bitter
taste_sweet
taste_pungent
taste_salty
meridian_heart
meridian_liver
meridian_spleen
meridian_lung
meridian_kidney
```

总计 11 个 question keys。

### TDD-TEST-011｜四气无 abstain

`qi.criteria` 必须恰好是：

```text
寒 / 凉 / 平 / 温 / 热
```

不得出现“证据不足”“未知”“其他”。

### TDD-TEST-012｜schema 外标签不可输出

runner 的 question construction 中不得存在：

- 五味：淡、涩；
- 归经：胃、胆、大肠、小肠、膀胱、三焦、心包。

### TDD-TEST-013｜新 held-out 与 few-shot 不重合

v0.2 五个测试药名不得出现在 v0.2 demonstrations 的 meta 中。

## 4. 成功标准

v0.2 仍是工程 pilot，不设置生产阈值。

通过条件：

1. 5/5 请求成功；
2. schema oracle 全部通过；
3. gold / 药名不泄漏到 target state；
4. 保存原生概率；
5. 生成四气 accuracy、五味/五脏归经 exact set 与 micro P/R/F1；
6. 同一冻结配置重复 3 次，报告稳定性，不挑最好的一次。

## 5. v0.1 的处理

v0.1 结果文件保留，因为它验证了 API、匿名化、gold 隔离、Actions secret 和重复运行机制。

但 v0.1 的“12 经输出”与项目真实输出契约不一致，因此：

- 不再用 v0.1 归经指标评估方案质量；
- 不再把“胃经假阳性”等 schema 外输出当作 v0.2 错误模式；
- v0.2 及以后只评价封闭字段内的分类。
