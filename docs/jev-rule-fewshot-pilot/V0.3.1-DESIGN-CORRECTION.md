# v0.3.1 Design Correction — 五脏功能群投影与样本一致性

> v0.3 Actions #11 仅作为设计检查，不作为有效 accuracy benchmark。
> 原因：评分 gold 与推理规则对“脾胃功能群”的处理不一致，且温性 held-out 的说明文档缺乏足够温性线索。

## 1. 五脏功能群投影

因为产品输出只保留心、肝、脾、肺、肾五个归经字段，传统资料中的六腑证候先进入相表里的五脏功能群：

- 胆 → 肝胆功能群 → 肝；
- 胃 → 脾胃功能群 → 脾；
- 大肠 → 肺与大肠功能群 → 肺；
- 小肠 → 心与小肠功能群 → 心；
- 膀胱 → 肾与膀胱功能群 → 肾；
- 三焦不机械固定投影，按上、中、下焦的具体功能和症候再判断相应五脏。

这不是声称“胃经就是脾经”，而是本项目在**只能输出五脏字段**时采用的工作投影。

推理 rules、few-shot 标准答案、held-out gold 必须使用同一投影方法。

## 2. Five-shot 修正

- 黄连：原药典含大肠经，在五脏功能群投影中增加肺；标准结果改为心、肝、脾、肺。
- 桂枝：原药典含膀胱经，在五脏功能群投影中增加肾；标准结果改为心、肺、肾。
- 其他 three-shot 不变。

说明文档同步增加相应的功能桥梁，例如泻痢→大肠/肺功能群、水肿→膀胱/肾水液功能群。

## 3. Held-out 修正

### 余甘子

原药典归肺、胃经。

五脏功能群投影：

```text
肺 → 肺
胃 → 脾
```

所以 v0.3.1 gold 为：肺、脾。

v0.3 #11 中 Jev 三次均预测“肺、脾”，该项原先被错误计为假阳性。

### 温性样本

删除紫苏子作为本轮 accuracy 样本。其药典虽为温，但当前说明文档“降气化痰、止咳平喘、润肠通便”没有足够明确的温性推理桥梁，违背“说明文档与结果内在一致”的测试原则。

替换为草豆蔻：

- 传统：辛，温；归脾、胃经；
- 功能：燥湿行气，温中止呕；
- 主治：寒湿内阻、脘腹胀满冷痛、嗳气呕逆、不思饮食；
- 五脏投影：脾。

其温性和脾胃功能群均能从说明文档内部直接推得。

## 4. 有效 benchmark 条件

v0.3.1 只有在以下条件同时满足时才计分：

1. 说明文档中存在与 gold 一致的推理桥梁；
2. few-shot 与 gold 使用同一五脏功能群投影；
3. target 仍是自然语言说明文档；
4. rules 仍只写推理方法，不重复 API 输出约束；
5. 不因 Jev 的预测结果反向修改单个样本 gold。

v0.3 #11 的问题属于 test contract 不一致，因此作废后重跑不视为针对模型错题调参。
