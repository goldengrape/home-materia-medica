# 《居家本草》编纂架构

> 版本：v1.0-draft
> 作用：把项目拆成相对独立的工作块，减少目录、证据、概念、正文互相牵连。

## 一、八个工作块

### ARC-WS-001｜Catalog：目录与身份
- 权威内容：entry ID、正式收录、主分类、标签、母条/子条/相关条目、研究深度建议、状态。
- 路径：`catalog/`。
- 不负责：判断功效、性味或归经。

### ARC-WS-002｜Method：编纂方法
- 权威内容：凡例、R/D/E/M、研究预算、停止规则、引用和安全表达。
- 路径：`docs/`。
- 不负责：某个食品的具体结论。

### ARC-WS-003｜TCM Concepts：中医概念
- 权威内容：Concept Trace、工作定义、原典/后世/现代教材层次、异说、映射边界。
- 建议路径：`concepts/`。
- 不负责：仅凭概念给现代食品定归经。

### ARC-WS-004｜Research：搜 + 整
- 权威内容：食品身份、来源、检索日志、证据卡、D/E、安全、机制、Concept Trace、冲突、未知、停止理由。
- 详细底稿：`references/entries/<entry-id>/research.md`。
- Jev 输入说明文档：`references/entries/<entry-id>/summary.md`。
- 执行器：`skills/home-materia-research/`。
- Research 不预先决定最终四气、五味、归经和阴阳增减，也不在 Jev 之前为这些候选定 M。

### ARC-WS-005｜Classification + Writing：判 + 写
- 判：`skills/home-materia-jev-mapping/` 读取 `summary.md`，输出四气、五味、五脏归经、每经阴阳增减主方向；随后依据 Research Dossier 对这些分类逐项标 M。
- 分类记录：`references/entries/<entry-id>/mapping.md`。
- 写：正文读取 `summary.md` + `mapping.md` + 必要的 `research.md`，形成面向读者的叙事。
- 正文路径：`entries/`、`scenes/`。
- 约束：正文不得重新研究、重新分类或自行提升 E/M。

### ARC-WS-006｜Quality：跨条目质量
- 检查身份重复、等级漂移、claim 可追溯性、术语一致、安全遗漏、evidence cutoff 与措辞强度。
- 建议路径：`qa/`。

### ARC-WS-007｜Publishing：发布
- 负责卷章、参见、索引、参考文献体例、术语表、附录和发布构建。
- Markdown 是正文源格式。
- 主要在线版本为 GitHub Pages 网页电子书。
- 每个正式版本在 GitHub Release 中附带 Markdown 文件包与 EPUB。
- 全书不设图片，因此 Publishing 不维护插图、照片、图表图片或图片版权流水线。
- 当前只冻结发布契约，不提前实现完整主题与构建系统。

### ARC-WS-008｜Tooling：自动化与 AI
- 包括 research skill、Jev mapping skill、未来 writing skill、元数据/TRACE/引用检查器、批次状态统计、OKF。
- 工具执行规则，但不能成为规则的唯一来源。

## 二、来源权威顺序

发生冲突时按以下顺序处理：

1. `docs/项目说明.md`：项目目标与边界；
2. `docs/居家本草编纂凡例-v1.0.md`：研究与证据规则；
3. `catalog/`：条目身份与收录边界；
4. `concepts/`：中医概念工作定义；
5. `references/entries/`：某条目的研究事实；
6. `entries/` / `scenes/`：面向读者的表达；
7. `skills/` / 脚本：执行上述规则；
8. `okf/`：派生的 AI 检索层。

下层与上层冲突时，修改下层，不能静默覆盖上层。

## 三、理想依赖

权威生产流程见 `docs/生产流程.md`。

```text
Catalog / Method / Concepts
          ↓
      搜：research.md
          ↓
      整：summary.md
          ↓
      判：mapping.md
      Jev + M
          ↓
      写：entry.md
          ↓
        Quality
          ↓
       Publishing
```

Tooling 横向支持，但不拥有业务结论。

## 四、关键接口

- ARC-IF-001 Catalog → Research：Research 必须使用稳定 entry ID、canonical name、parent/related entries 与 R 深度；不得自行创建同义主条目。
- ARC-IF-002 Method → Research：research skill 必须读取凡例；冲突时以凡例为准。
- ARC-IF-003 Concepts → 整理：关键中医概念使用既有 Concept Trace；传统习惯功效词优先由原子分类在写作层派生。
- ARC-IF-004 Research → Summary：`summary.md` 只能压缩和组织 `research.md` 已有资料，不得预写 Jev 分类答案。
- ARC-IF-005 Summary → Jev：Jev 正式生产输入只能是 `summary.md`；不得另造答案导向 feature packet。
- ARC-IF-006 Jev → Mapping：先保存 Jev 原始分类与 score，再依据 `research.md` 对这些分类逐项标 M；M 不修改 Jev，Jev 不提升 M。
- ARC-IF-007 Mapping → Writing：正文使用资料 + 分类结果写作；传统习惯词可按“归经 + 阴阳增减 + 语境”派生。
- ARC-IF-008 Writing → 上游：缺事实回“搜/整”，分类问题回“判”；正文不得自行补研究或重分类。
- ARC-IF-009 Quality → 上游：身份错回 Catalog；资料错回 Research；摘要失真回 Summary；分类错回 Mapping；表达越界回 Writing。

## 五、STOP 条件

- ARC-STOP-001：目录身份不清楚，不开始深度研究。
- ARC-STOP-002：核心问题无限扩张，先回到 R 等级和研究预算。
- ARC-STOP-003：中医概念含义不明，先做 Concept Trace。
- ARC-STOP-004：正文需要 dossier 中不存在的强结论，退回 Research。
- ARC-STOP-005：工具输出与 docs 冲突，修工具或 docs，不直接采用工具结果。
- ARC-STOP-006：pilot 尚未完成，不进入大规模批处理。

## 六、架构原则

> Catalog 管“是什么”；Method 管规则；Concepts 管底层中医概念；Research 负责“搜 + 整”；Jev/M 负责“判”；Writing 负责“写”；Quality 管有没有跨层漂移；Publishing 管怎么成书；Tooling 只负责让这些步骤更省力。
