# 《居家本草》发布方案

> 版本：v1.0-draft
> 状态：Publishing Contract
> 作用：固定发布介质和构建边界；实现细节在 RM-PHASE-080 再决定。

## 一、正文源格式

Markdown 是唯一正文源格式。

`entries/`、`scenes/` 及必要的前言、附录、术语表均以 Markdown 维护。网页和 EPUB 从同一套正文源构建，不分别维护第二份正文。

## 二、正式发布物

### PUB-OUT-001｜GitHub Pages

作为主要在线阅读版本，要求：

- 可按卷、章节和条目导航；
- 支持条目间参见与锚点链接；
- 支持参考资料链接；
- 移动端与桌面端均可读；
- URL 尽量稳定，便于引用和分享。

### PUB-OUT-002｜Release Markdown Bundle

每个正式版本在 GitHub Release 中提供 Markdown 打包文件，至少包含：

- 正文；
- 目录；
- 必要的术语表、凡例与附录；
- 版本信息。

研究底稿、内部 QA、OKF 和项目治理文件是否进入发布包，由发布阶段另定；默认不作为读者版正文的一部分。

### PUB-OUT-003｜EPUB

每个正式版本在同一 GitHub Release 中提供 EPUB。

EPUB 与 GitHub Pages 使用同一 Markdown 正文源，允许样式不同，不允许内容事实不同。

## 三、无图片原则

### PUB-CON-001

全书不设图片。

因此项目不维护：

- 插图与照片；
- 食材图、药材图；
- 装饰性章节图片；
- 图注与图号；
- 图片版权与授权记录；
- 图片压缩、响应式图片或 EPUB 图片兼容流程。

需要表达结构关系时，优先使用：

- Markdown 表格；
- 列表；
- 引用块；
- 纯文本层级；
- 必要时使用简单字符结构，而不转成图片。

## 四、构建原则

1. 单一正文源：Markdown → Pages / Markdown Bundle / EPUB。
2. 构建只做格式转换、导航、索引和样式，不改写研究结论。
3. Release 使用版本号，与正文 evidence cutoff 和 CHANGELOG 对应。
4. GitHub Pages 默认展示最新发布版；历史版本通过 Release 保留。
5. 构建应可重复，后期优先用 GitHub Actions 自动生成。

## 五、暂缓决定

以下实现细节到 RM-PHASE-080 再选择：

- GitHub Pages 使用哪种静态站点生成器；
- EPUB 具体构建工具；
- 主题字体与 CSS；
- 脚注、尾注或条目末参考资料的最终展示；
- Release 包目录结构；
- 是否同时提供单文件合并版 Markdown。
